# Node command wrapper reference

`node.json` retains canonical output generated by npm's ISC-licensed
[cmd-shim](https://github.com/npm/cmd-shim), with its license alongside it.
The references were generated from cmd-shim 7.0.0 bundled with npm 10.9.8 and
cmd-shim 9.0.2 bundled with npm 12.0.2. Each record binds the generator's
`lib/index.js` SHA-256. These are template identities, not a claim that an
installed wrapper reveals the user's exact npm version.

For each generator, a temporary target `node_modules/@test/cli/bin/run.js`
contained `#!/usr/bin/env node` followed by LF and a harmless JavaScript body.
Calling `cmdShim(target, "node_modules/.bin/reference")` produced the extensionless
shell script, `.cmd` and `.ps1` files. Only the exact relative target slot
`../@test/cli/bin/run.js` (backslashes in `.cmd`) became `{{TARGET}}`; every other
byte, including line endings and whitespace, is retained in the JSON strings.
No wrapper was executed to establish Windows compatibility.

The verifier derives that slot from already inventoried command targets. It
accepts only the exact Node shebang and an ASCII path subset without shell
expansion characters. An installation prefix containing spaces is outside the
substituted relative slot. All three regular, bounded, non-reparse files must
match a single generator family. Altered bytes, partial sets, mixed families
and unsupported shebangs fail verification. Existing POSIX symbolic-link
verification remains separate. Staged bundles need not contain generated wrappers;
once any regular wrapper is found, its complete triplet is mandatory. The npm
validator additionally requires every declared command's triplet after Windows
installation, so deleting all wrappers cannot pass installed acceptance.

To update a reference, inspect the exact npm dependency source, retain its license
and source hash, generate all three files through that real implementation, and
compare output for the five pinned CLI commands and nested/scoped targets. Add
mutation and mixed-family tests before accepting new templates. Do not loosen
verification through a target-only parser or by accepting arbitrary script bodies.
Linux generation equality does not replace actual Windows installation and
execution in PowerShell, cmd and the supported terminal environments.
