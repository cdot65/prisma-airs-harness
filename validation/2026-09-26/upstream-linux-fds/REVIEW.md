# Fork-safe Linux descriptor cleanup prerequisite

Adapted b086ad5493 (PR 47654) without the newer Command wrapper. Existing callers still use the same function. Linux only: replace allocating /dev/fd iteration after fork with close_range(CLOEXEC), falling back to stack-buffer getdents64 and fcntl. CLOEXEC preserves Rust's error-report pipe until successful exec. Keep-list iteration needs no allocation/sorting; parser bounds-checks record lengths before slicing. Errors preserve upstream best-effort launch behavior rather than implying sandbox containment.

Adversarial cases pass: close_range denied; lowered RLIMIT with high open FDs; explicit preserved FDs; pipe/socket/file inheritance; unchanged parent flags; executable not found with fallback; both cleanup syscalls denied. Existing PTY group, stream and teardown tests also pass. Native Mac code is unchanged behind cfg; macOS MCP integration remains a subsequent gate.

The first compile exposed missing test-only tempfile dependency and sibling helper visibility; corrected through the existing workspace dependency and pub(super), not a product API. Cargo lock changed by one dependency edge. Required just bazel-lock-update ran successfully on Mac and regenerated bytes match the existing MODULE.bazel.lock; no artificial lockfile edit is needed.
