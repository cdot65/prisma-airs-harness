# Interrupted answer/plan preservation review

Adapt upstream 529bcb2fdf (PR 45549) to the existing AIRS stream controller. One shared helper drains the answer and plan into existing consolidation events before termination clears controllers. Normal completion reuses the same path. Remove redundant answer-only drains in AIRS company and MCP recovery, retaining authentication_pending before cleanup. This is display/history consolidation, not an inference retry or model-context rewrite.

Counterexamples reviewed: unterminated delta, committed live tail, repeated finalization, pending usage insertion, failure/cancellation, safety-policy error, resizing/raw mode. Taking controllers makes repeated cleanup idempotent. The existing had_live_tail guard prevents inserting a duplicate rendered plan; source consolidation retains text for reflow. Safety-buffering stores status/retry metadata, not withheld response bytes, and is still cleared after received streams are consolidated. No hidden provider safety content is obtained. No credentials or routing headers change.

AIRS regression specifically retains a draft and queued request while authentication is pending; two finalization calls must yield exactly one consolidated source and no operation submission. This tests the common cleanup contract; it is not a claim of live CAS or MCP reauthentication acceptance. App tests drive server notifications and real transcript event application, checking preserved source and stable normalized content over widths and raw mode. Snapshots must be visually reviewed before acceptance.

Pending: focused and complete TUI tests, snapshot review, scoped Clippy, formatting, native validation. No final feature scores until these pass. Subagent activity deferral is a separate follow-on slice and is not claimed by this patch. Self-review uses explicit counterexamples but is not a claim of independent bias-free review.
