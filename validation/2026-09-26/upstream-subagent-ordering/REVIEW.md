# Subagent activity ordering review

Adapt e29eceb751 (PR 46867) to the existing AIRS lifecycle. Defer child completion activity while the parent answer controller is active, then use the existing authoritative answer consolidation before publishing activity. At normal or abnormal termination, drain only lifecycle events and retain queued prompts without opening them. Late child notifications after termination render immediately even when an old prompt remains unresolved.

The activity-only drain preserves FIFO within activity events and retains prompt order. The catch-all deliberately retains all non-activity queue entries, including future prompt variants, rather than opening or dropping them. It invokes existing history handlers; it does not approve a tool, send a user turn, or trigger authentication. No new queue type, service, model field or credential scope is introduced. The upstream dynamic-activity renderer is absent in this branch and was not imported as an unrelated prerequisite.

Counterexamples covered by unchanged upstream tests: activity before remaining deltas; activity after all deltas but before authoritative completion; missing final delta repaired by the final item; interrupted answer; failed/completed turn without final item; queued blocking question stays closed; second child completing after turn termination remains visible; backend resolution still removes retained prompt. An inline rendering snapshot verifies the complete answer appears once before the completion row. Existing AIRS question-recovery regressions additionally cover draft preservation and no automatic submission during authentication recovery. This patch concerns parent answer ordering; it does not introduce a new plan renderer or change inference request/retry behavior.
